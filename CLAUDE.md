## Architecture

### Layered Design

1. **UI Layer** — CLI (click, `cli.py` ~2200 lines, 20+ command groups), Web/FastAPI (optional `[web]` extra), macOS .app (Swift WKWebView browser)
2. **Workflow Engine** — DAG-based (n8n-inspired): topological sort → node execution → data passing
3. **AI Capability** — `FusionMLXClient` (HTTP → fusion-gateway :11432 → fusion-mlx), `NLWorkflowGenerator` (NL → workflow), `KBClient` (HTTP → fusion-rag :11436)
4. **Collaboration Space** — multi-agent workspace: agents, artifacts, chat (SSE), knowledge, members, permissions, shared context (aiosqlite-backed)
5. **Orchestrator** — `AgentOrchestrator` multi-agent runtime with executors + comm bus
6. **System Capability** — macOS nodes via AppleScript/osascript + pathlib/shutil + CDP browser control

### Core Engine (`fusion_cowork/engine/`)

- **`node.py`** — `BaseNode` (abstract), `NodeRegistry` (class-level registry), `@register_node` decorator, type coercion (`_coerce_int/bool/number/array`) for LLM-generated string params
- **`workflow.py`** — `Workflow` (DAG container, cycle detection, topological sort), `WorkflowEngine` (async executor, progress callbacks, cancel, retry)
- **`scheduler.py`** — `TaskScheduler` (APScheduler-based cron)
- **`enhanced_scheduler.py`** — V0.2: calendar view, task dependency, stats
- **`optimizer.py`** — V0.2: AI workflow analysis, bottleneck detection
- **`hooks.py`** — `HookManager` + `HookEvent` enum (14 events: pre/post_node_execute, workflow_start/end/cancel, permission_request, config_change, agent_start/stop, notification, node_error, session_start/end, pre_compact)
- **`permission.py`** — `PermissionManager`, 15-action matrix (view/edit/share/transfer artifact, etc.). **v0.3.0**: `PermissionLevel.CONFIRM` 默认 (可用+安全); check() 重排 approve→allow / deny→deny / HIGH_RISK_NODES→deny / else→allow; HIGH_RISK_NODES ~30 节点 (含 shell/REPL/file_copy/move/disk_cleaner/desktop_clean/app_lifecycle/screen_capture/clipboard/notification/mouse_*/keyboard_*/computer_use_loop/cdp_*); approve() 全 level 生效. **v0.4.5** (issue #73): HIGH_RISK_NODES 委托 `guard.evaluate` (UDS JSON-RPC `/tmp/fusion-guard.sock`, `security/guard.py::GuardClient`); 低风险节点留本地不走 guard IPC; opt-in (`FUSION_GUARD_ENABLED=1`+socket 存在, 默认 OFF 零行为变化); verdict allow→True, block/L4→False, requires_approval(L3)→存 pending 待 `confirm_guard`→本地 approve 规则, preview/redact→保守 deny; guard 不可达→`guard.rules.dump` 缓存 `~/.fusion-guard/rules-cache.json` fail-closed (高风险 DENY 非 fail-open); `_node_to_guard_content` 映射节点→(content, content_type); `desk.permission.confirm_guard` RPC 转发
- **`session.py`** / **`events.py`** / **`schema.py`** / **`ast_diff.py`** — session store, event emitter, JSON schema helpers, AST diff (migrated from fusion-multi-node)

### Key Patterns

- **Lazy Import** (`fusion_cowork/__init__.py`): `__getattr__`-based lazy loading via `_LAZY_IMPORTS` dict (~216 entries). Keeps `import fusion_cowork` fast; modules load on first attribute access.
- **Node Name Aliases** (`NODE_NAME_ALIASES`): Chinese user-friendly names → backend node names, registered via `NodeRegistry.register_alias()`. Used by `NLWorkflowGenerator`.
- **Type Coercion**: `_coerce_*` functions convert LLM string outputs ("10", "true") to declared JSON Schema types. Applied automatically in `NodeRegistry.create()`.
- **Workflow Serialization**: `Workflow.to_dict()/from_dict()` supports both dict and list node formats. Edges define data flow between nodes.

### Collaboration Space (`fusion_cowork/space/`)

Multi-agent workspace layer (V0.3+, M6-M8 milestones). `space/store.py` is the aiosqlite persistence layer (12 tables: agents, artifacts, chat, members, sessions, sidebar_modules, notifications, etc.). Submodules: `api.py` (FastAPI endpoints + SSE chat), `agent_runtime.py`, `artifact.py` (CRUD + ownership + permission), `chat.py`, `knowledge.py` (KBClient bridge), `member.py`, `permission.py`, `fsb.py` (module registry + notifications), `shared_context.py`, `models.py`, `service.py`. ## Conventions

- setuptools build backend with `[tool.setuptools.packages.find]`
- Code style: 4-space indentation (multiples of 4), **no docstrings**, always include logging
- Ruff config: line-length 120, target py311, rules E/F/W/I/UP/B/SIM/RUF (many noise rules ignored — see `pyproject.toml`)
- IPC between fusion-studio (Swift GUI) and Python services uses JSON-RPC 2.0 over Unix Domain Socket
- Node name aliases map Chinese user-friendly names → backend names
- Two-key auth model: `FUSION_CLIENT_KEY` is the **fusion-gateway client key**, NOT the mlx backend key (separate auth layers). 401 → check key source. (issue #204: resolved via `fusion_core.config.client_key()` with canonical-name-only fallback; legacy aliases `FUSION_MLX_API_KEY`/`MLX_API_KEY` deprecated-but-honored by fusion-core; gateway admin key likewise `FUSION_ADMIN_KEY` via `fusion_core.config.admin_key()`.)
